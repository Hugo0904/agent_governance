# Task 文件契約（Task Document Contract）

本文件定義任務檔的固定結構，目標是讓同一份 `task.md` 可被人類與 AI 穩定接手。

## 1. 固定區塊（強制）
任務檔必須包含且依序維持以下四塊：

1. 原始任務內容（Immutable）
2. 討論後且 AI 整理的詳細內容（Confirmed）
3. 過程 Checklist
4. 備註 / 使用方式 / 交接說明

## 2. 區塊規則（強制）

### 2.1 原始任務內容（Immutable）
- 僅允許附加註記，不可改寫原文。
- 若原始內容有誤，需於第 4 區塊補「修訂說明」，不可直接改動原文。

### 2.2 AI 整理內容（Confirmed）
- 需整理為可執行的規格，至少包含：
  - 任務目標
  - 範圍 / 非範圍
  - 執行步驟
  - 驗收標準
  - 風險與依賴

### 2.3 過程 Checklist
- 使用 markdown checkbox（`- [ ]` / `- [x]`）。
- 每個項目需可被客觀驗證，不可使用模糊描述。
- 只追蹤需求完成度；執行細節仍記錄在 task log。

### 2.4 備註 / 使用方式 / 交接說明
- 必須提供下一位接手者可直接使用的說明。
- 建議包含：
  - 如何啟動此任務
  - 需要的環境變數或路徑
  - 下一步建議

## 3. 任務撰寫建議（可選，但強烈建議）
- 任務開頭先用一到兩句寫清楚「要做什麼」與「為什麼要做」。
- 若任務涉及特定領域，直接寫出領域脈絡，例如金流、遊戲平台或 PR review。
- 補上關鍵上下文：涉及專案、參考文件、後台路徑、API 文件、測試帳號類型、已知限制。
- 若已有初步判斷，也可在任務中寫「可參考某份規範或某位代理」；這是提示，不是硬綁定。
- 若有待確認事項，直接列成清單，讓 AI 在 Intake 階段優先逐項確認。

建議使用這種簡短寫法：

```md
任務目標：接入新的第三方支付供應商
領域：金流 / 代收
涉及專案：s8_agent、s8_midway、s8_user
參考資料：<文件連結或路徑>
已知資訊：廠商代號、商戶後台、回調需求
待確認：是否包含代付、是否要新增後台設定欄位
```
