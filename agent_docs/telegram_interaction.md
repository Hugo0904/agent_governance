# Telegram 互動規則

本文件僅適用於 Telegram 來源任務。

來源判斷：
- `AI_TASK_SOURCE=telegram`，或
- 等價執行來源標記顯示來自 Telegram adapter。

## 1. 指令互動（強制）
- `/codex`、`/ai` 執行時，需回報：接收、開始、task id、結果、耗時。
- 完成後優先提供 Telegram 按鈕續問。
- 保持純文字續問相容（含 `1/2` 這類選項回覆）。

## 2. 任務延續（強制）
- 同一線程續問時，沿用既有 `task_id + progress`。
- 若切換為新會話，應明確建立新 task。
- 文字回覆需可讓使用者快速判斷：
  - 目前線程 / task
  - 任務狀態
  - 下一步操作入口

## 3. 單向通知（電腦端，強制）
- 適用：電腦端發起的專案任務（不論是否由 Telegram 發起）。
- 每次任務完成後，若設定了 Telegram chat，需推送一則完成通知。
- 通知內容保持精簡：`task_id`、狀態、耗時、下一步建議（若有）。
- 此通知流程不要求電腦端對話上下文與 Telegram 強制同步。

## 4. 內容風格（強制）
- 以可掃讀格式為主，避免冗長執行過程。
- 優先摘要結果與可執行下一步。
- 不回傳密鑰、token、密碼、Webhook URL。
