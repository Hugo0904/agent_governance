# 語言規範目錄

本目錄用於存放「程式語言本身成立」的穩定規則，讓跨語言工程原則與語言特性分開管理。

## 角色
- 本檔是語言規範的第二層索引。
- `AGENTS.md` 應只判斷「是否進入語言主題」，不應把每一份語言 leaf 直接平鋪在 root。
- 具體要讀哪份語言規範，由本檔往下分流。

## 子文件索引
- `agent_governance/agent_docs/languages/language_rule_template.md`
  只在建立新的語言規範文件時使用。
- `agent_governance/agent_docs/languages/php.md`
  只在目標專案或主要修改範圍明確是 PHP，且需求涉及 PHP 語言特性、命名、型別、陣列、例外、相容性或 PHP code review 檢查點時使用。

## 使用時機
- 上層已判定本次需求涉及語言層級規則，需先來本檔決定往下讀哪一份語言文件。
- 規則來自語言語意、語法、標準函式庫或常見命名慣例。
- 同一語言在多個專案中都可能成立。
- 內容可被 reviewer 穩定檢查，不依賴單一專案資料表或業務真相。

## 不放這裡
- 單一專案的 framework 版本限制、框架慣例或目錄結構。
- 單一專案的資料模型、業務語意或功能流程。
- 只屬於單次任務的暫時決策。
- 只是示例、片段口語指正，尚未抽象成可重用原則的內容。

## 檔名建議
- 一般情況使用 `<language>.md`。
- 只有版本差異會改變規則時，才使用 `<language>_<major>.md`。
- 跨語言共通的文件寫作規則，放回 `agent_docs/` 根目錄，不放在這裡。

## 建議結構
- `適用範圍`：說明規則成立的語言範圍與邊界。
- `穩定特性`：整理語言語意、語法限制或標準行為。
- `命名與風格`：整理語言層級成立的命名與寫法慣例。
- `常見風險`：整理語言常見陷阱、反模式或 reviewer 應注意的點。
- `不放這裡`：列出應回到專案規則或任務檔的內容。

## 與其他文件的邊界
- 跨語言工程觀念：回到 `engineering_principles.md`。
- 長期 md 文件怎麼寫：回到 `markdown_authoring_rules.md`。
- 專案 / 框架 / 版本 / 業務真相：回到專案 `AGENTS.md` 或 `agent_rules/*.md`。
