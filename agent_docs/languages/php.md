# PHP 語言規範

本檔用於整理 PHP 語言本身成立的穩定規則，不放單一專案、單一 framework、單次任務決策或未確認示例。

## 適用範圍
- PHP 語言語意、型別行為、標準函式庫使用習慣。
- PHP 專案常見的檔案 / 類別 / 方法 / 屬性命名與拆分慣例。
- 跨多個 PHP 專案都可能成立的 reviewer 檢查點。

## 穩定特性

### 型別與比較
- 整理 `null`、`false`、空字串、空陣列、數字字串等在 PHP 內的型別行為。
- 整理需要使用嚴格比較的場景與原因。

### 陣列與資料結構
- 整理陣列是有序 map 的語意與常見誤用。
- 整理關聯陣列、索引陣列、資料物件在 PHP 內的邊界。

### 作用域與狀態
- 整理 static、global、可變共享狀態在 PHP 內的風險。
- 整理 function、method、property 的責任邊界。

### 錯誤與例外
- 整理錯誤處理、例外傳遞、失敗訊號表達方式的語言層級原則。

## 命名與風格

### 檔案與類別
- 整理檔名、類別名、namespace 的對齊方式。
- 整理類別職責與檔案切分原則。

### 方法與 helper
- 整理方法名稱應表達的責任、層次與剩餘差異。
- 整理 helper 命名是否重複外層上下文的判斷方式。
- 若檔名、類別名或 namespace 已明確限定領域，方法 / helper 名稱只描述剩餘差異，不再重複外層已提供的語意。

### 參數與回傳
- 整理參數命名、回傳型態、資料形狀表達方式。
- 整理何時應回傳資料、狀態、例外或訊息鍵。

## 常見風險

### 語言陷阱
- 整理寬鬆比較、隱式型別轉換、空值判斷不清等常見問題。

### 可讀性風險
- 整理過長方法、隱含副作用、資料形狀不明、上下文重複命名等 reviewer 常見意見。

### 相容性風險
- 整理舊版 PHP 常見限制、相容寫法與升級時需注意的語言差異。

## 從 engineering_principles 搬遷時的落點
- 若規則是在談 PHP 的 `class`、`interface`、`trait`、`method`、`property`、`namespace`、檔名對齊方式：
  放到 `命名與風格`。
- 若規則是在談 PHP 的型別轉換、嚴格比較、陣列語意、空值處理、例外傳遞：
  放到 `穩定特性`。
- 若規則是在談 reviewer 常抓到的 PHP 反模式、可讀性問題或相容性陷阱：
  放到 `常見風險`。
- 若規則拿掉 PHP 仍然成立，例如分層邊界、資料模型優先、live data 相容性、規則要可驗證：
  留在 `engineering_principles.md`，不要搬進來。

## 不放這裡
- 單一專案的 framework 版本限制、ORM 寫法、框架目錄結構。
- 單一專案的資料模型、業務真相、功能流程。
- 只在某次任務成立的例外處理。
- 仍依賴具體案例名稱、尚未抽象成通用規則的說法。
